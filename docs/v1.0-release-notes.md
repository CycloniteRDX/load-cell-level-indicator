# v1.0 Functional Prototype

## Release identifier

```text
v1.0-functional-prototype
```

## Release status

This release establishes the current firmware as the first complete and reproducible functional prototype of the load-cell level indicator.

It does not introduce a new application feature beyond the previously validated `v0.16-direct-avr-entrypoint` milestone. Instead, it closes the first development phase by adding project-level documentation, a complete native-test runner and a clearly defined stable baseline.

## Purpose

The firmware measures the weight of a container through an HX711-connected load cell and represents the measured level through three indicator outputs.

The project was intentionally developed in progressive stages, starting from an Arduino/Bogde prototype and ending with:

- A project-owned HX711 driver.
- Modular application components.
- Project-owned hardware-abstraction interfaces.
- Direct AVR GPIO, Timer1, EEPROM and USART0 backends.
- A project-owned bare-metal entry point.
- Persistent calibration.
- Physical and serial controls.
- Native unit tests.
- Reproducible build, upload and validation instructions.

## Production target

The supported production target is:

```text
Arduino Nano
ATmega328P
16 MHz
new Nano bootloader configuration
```

The production PlatformIO environment is:

```text
nanoatmega328new
```

It uses:

```ini
platform = atmelavr
board = nanoatmega328new
```

It does not use:

```ini
framework = arduino
```

The firmware still uses AVR-GCC, AVR-LibC and the existing Nano bootloader.

## Main capabilities

### Measurement

- HX711 communication through a project-owned driver.
- Configurable sample collection.
- Startup tare.
- Manual tare.
- Weight conversion using a runtime calibration factor.
- Fixed-point serial output without floating-point `printf`.

### Calibration

- In-place calibration with a known reference mass.
- Physical-button calibration flow.
- Serial-console calibration flow.
- Calibration cancellation.
- Validation of the calculated factor.
- EEPROM persistence.
- Default-factor fallback when no valid EEPROM record exists.

### Level indication

- `VERY_LOW`, `LOW`, `MEDIUM` and `HIGH` logical levels.
- Three physical LED outputs.
- Blinking very-low warning.
- Hysteresis around level boundaries.
- Temporary visual patterns for:
  - Tare.
  - Calibration steps.
  - Calibration success.
  - Calibration error.

### Input

- Debounced physical buttons.
- Short-press and long-press behaviour.
- Case-insensitive serial commands.
- Explicit handling of pending input during blocking operations.

### Platform ownership

The production firmware owns:

- `main()`.
- GPIO configuration and access.
- Timer1 millisecond timebase.
- Millisecond delay.
- EEPROM access.
- USART0 initialization.
- Interrupt-driven USART0 reception.
- Console abstraction.
- HX711 communication.

The production execution path does not use Arduino:

- `setup()`.
- `loop()`.
- Arduino `main()`.
- Arduino Timer0 timekeeping.
- Arduino `millis()`.
- Arduino `delay()`.
- `HardwareSerial`.
- Global `Serial`.
- Arduino EEPROM.
- Arduino GPIO functions.

## Build and upload

Build the production firmware:

```powershell
pio run
```

Upload it:

```powershell
pio run -t upload
```

Open the console:

```powershell
pio device monitor -e nanoatmega328new
```

The serial monitor must be closed before uploading because the COM port cannot be owned by both processes simultaneously.

## Hardware scope

The current prototype expects:

- Arduino Nano.
- HX711 module.
- Load cell.
- Two momentary buttons.
- Three low-voltage indicator LEDs.
- Current-limiting resistors.
- USB power/programming during development.

The repository does not include a finished 24 V output stage.

A 24 V tower light must use suitable external drivers and must not be connected directly to the ATmega328P pins.

## Known limitations

This release is a functional prototype rather than an industrial product.

Known limitations:

- Startup waiting is blocking.
- Tare sample collection is blocking.
- Calibration sample collection is blocking.
- Some temporary result indications are blocking.
- There is no complete application-level fault-state machine.
- There is no watchdog recovery strategy.
- HX711 faults do not yet have comprehensive runtime diagnostics.
- There is no stable-weight detector.
- There is no advanced outlier rejection.
- Thresholds are compile-time constants.
- The calibration reference mass is a compile-time constant.
- Configuration cannot be edited through a complete user interface.
- EEPROM currently stores one calibration record rather than a wear-levelled journal.
- Only the HX711 measurement backend is implemented.
- Only the ATmega328P Nano production platform is implemented.
- No LoRa communication is included.
- No custom PCB is included.
- No final 24 V power architecture is included.
- No enclosure, EMC or environmental validation has been completed.
- The firmware has not been certified for commercial or safety-critical use.

## Deliberately deferred work

The following work is intentionally deferred until after this release:

1. Non-blocking startup, tare and calibration state machines.
2. Explicit fault handling and diagnostics.
3. Watchdog integration.
4. Stable-weight and outlier detection.
5. 24 V power and output-driver design.
6. Custom PCB development.
7. Alternative measurement backends such as NAU7802 and ADS1232.
8. LoRa communication.
9. Source-tree restructuring if project growth justifies it.
10. A separate educational repository with heavily annotated versions.

These items are not required for the `v1.0-functional-prototype` definition of done.

## Release acceptance criteria

The release is defined as complete when:

- The production firmware is functionally validated.
- The production environment is bare-metal.
- Arduino Core is absent from the production execution path.
- The Nano bootloader remains functional.
- All 177 native tests pass.
- Static SRAM and Flash usage are recorded.
- The repository contains a complete `README.md`.
- The repository contains a one-command native regression script.
- Known limitations are documented.
- Deferred work is documented.
- The release branch is merged into `main`.
- The annotated `v1.0-functional-prototype` tag is created.
- The remote repository contains the tag.
- The final working tree is clean.
