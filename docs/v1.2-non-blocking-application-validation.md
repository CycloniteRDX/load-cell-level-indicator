## Purpose

This milestone removes the remaining multi-second application stalls caused by
HX711 startup, tare and calibration sampling.

The firmware now represents long-running work as explicit cooperative states.
Every call to `app_update()` performs at most one state-machine step and reads
at most one already-ready HX711 conversion before returning to the superloop.

The milestone does not add an RTOS, dynamic allocation, asynchronous EEPROM
programming or buffered USART transmission.

---

## Implemented behaviour

### Cooperative startup

```text
initialize peripherals
    -> poll HX711 readiness from app_update()
    -> load persistent configuration once
    -> enter NORMAL_OPERATION or TARE_REQUIRED
```

If the first conversion is not ready within 2000 ms, the application enters a
latched `FAULT` state. The superloop continues running, the HIGH LED blinks and
received input is rejected immediately instead of being queued for later.

### Incremental sample collection

The scale collector has four explicit states:

```text
IDLE
IN_PROGRESS
COMPLETE
ERROR
```

It provides these guarantees:

- Zero reads are performed while the HX711 is not ready.
- At most one raw conversion is read by one collector update.
- The 20-sample sum is safe for the complete signed 24-bit HX711 range.
- Completion, error and cancellation do not modify the active offset or
  calibration factor by themselves.
- Completed averages are applied only by the application after the required
  persistent-storage operation succeeds.

### Operational tare

```text
t or deliberate D4 hold
    -> TARE_SAMPLING
    -> collect 20 samples cooperatively
    -> save and verify candidate offset
    -> apply candidate offset
    -> NORMAL_OPERATION
```

During sampling, `q` or a new D4 press cancels before another conversion is
read. Cancellation, sampling failure, timeout or EEPROM failure preserves the
previous active tare.

The collection has a 5000 ms total timeout. Elapsed-time checks use unsigned
subtraction and remain valid across `millis()` overflow.

### Calibration

Calibration now uses four explicit application states:

```text
CALIBRATION_WAITING_FOR_ZERO
CALIBRATION_ZERO_SAMPLING
CALIBRATION_WAITING_FOR_MASS
CALIBRATION_MASS_SAMPLING
```

The zero phase collects, saves and verifies a candidate tare before applying
it. The reference-mass phase collects its own 20 samples incrementally. If the
new calibration factor cannot be saved, the previous active factor is restored.

Cancelling after a successfully completed zero phase keeps the newly persisted
tare while leaving the previous calibration factor active.

### Temporary result patterns

Finite success and error patterns are owned by:

```text
APP_STATE_RESULT_PATTERN
```

While this state is active:

- D4 and D8 are sampled but cannot start work.
- A button press that begins during the pattern is suppressed until release.
- UART input receives `Result indication is active.` and is discarded.
- The transition back to the saved state occupies one complete update.
- Normal work can begin only on the following `app_update()` call.

### Removed blocking interfaces

The following compatibility interfaces have been removed:

```text
scale_tare()
scale_read_net_counts()
scale_read_weight()
```

Normal measurement uses `scale_try_read_weight()`. Tare and calibration use the
incremental collector API.

## Physical validation

### 1. Startup with a valid stored tare

Procedure:

1. Establish and persist a valid tare.
2. Add a known load.
3. Reset the Nano without moving the load.
4. Observe startup, console output and level indication.

Expected:

- Startup does not redefine the existing load as zero.
- The stored calibration and tare are loaded once.
- Normal measurement resumes after HX711 readiness is observed.
- Buttons and UART input received before startup completion do not execute
  later.

### 2. Cooperative startup fault

Safe fault-injection procedure:

1. Remove power from the Nano and HX711.
2. Disconnect the HX711 `DOUT` wire from Nano D2.
3. Connect Nano D2 to +5 V through a 10 kOhm resistor so the input remains
   deliberately high. Do not leave D2 connected to the HX711 output.
4. Restore power and wait for more than two seconds.
5. Send one serial byte and operate both buttons.
6. Remove power and restore the normal D2-to-`DOUT` connection after the test.

Expected:

- `app_init()` returns and the firmware does not freeze.
- After approximately 2000 ms, the application enters the latched fault state.
- Only the HIGH LED blinks with the fault pattern.
- Serial input receives `FAULT: Reset required.` immediately.
- Button activity does not become a tare or calibration action.
- Normal operation returns after correcting the wiring and resetting.

Result:

```text
PENDING
```

- The deliberate hold starts exactly one tare.
- The new press cancels the active collection.
