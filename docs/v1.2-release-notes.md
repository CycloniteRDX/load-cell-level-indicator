# v1.2 Non-Blocking Application

## Release identifier

```text
v1.2-non-blocking-application
```

## Release date

```text
2026-08-10
```

## Release status

This release removes the remaining multi-second application stalls caused by
HX711 startup, tare and calibration sampling.

Long-running work is now represented by explicit cooperative states. One call
to `app_update()` reads at most one already-ready HX711 conversion and then
returns to the bare-metal superloop.

The firmware therefore continues updating buttons, serial input, timeouts and
LED patterns while a 20-sample operation is in progress.

## Problem resolved

`v1.1` collected all tare or calibration samples inside one function call:

```text
start operation
    -> wait for 20 HX711 conversions
    -> return after approximately two seconds at 10 SPS
```

USART reception could continue in its interrupt handler, but `app_update()`
could not process the received bytes, button events or future communication
work until the complete sample set had finished.

`v1.2` performs:

```text
start operation
    -> store operation state and progress
    -> return to superloop

each later app_update()
    -> process the input policy
    -> read zero or one ready conversion
    -> update state and indicators
    -> return to superloop
```

## Main capabilities added

### Cooperative startup

`scale_init()` configures the HX711 without waiting for its first conversion.
The application polls readiness from `app_update()` and loads persistent
configuration exactly once after the HX711 becomes ready.

If readiness is not observed within 2000 ms, the application enters a latched
fault state instead of remaining inside a permanent wait loop:

```text
APP_STATE_STARTUP_WAIT_FOR_SCALE
    |
    +--> ready   -> APP_STATE_STARTUP_LOAD_CONFIGURATION
    |
    +--> timeout -> APP_STATE_FAULT
```

The HIGH LED blinks in the fault state. UART input receives
`FAULT: Reset required.` and button activity cannot start work.

### Incremental scale collector

The scale module now exposes a stateful raw-sample collector:

```text
SCALE_SAMPLE_COLLECTION_IDLE
SCALE_SAMPLE_COLLECTION_IN_PROGRESS
SCALE_SAMPLE_COLLECTION_COMPLETE
SCALE_SAMPLE_COLLECTION_ERROR
```

Its contract guarantees:

- At most one raw read per update.
- No raw read while `DOUT` reports not ready.
- Safe accumulation across the complete signed 24-bit HX711 range.
- Sticky completion and error states until the result is taken or cancelled.
- No direct modification of tare offset or calibration factor.

The application decides when a completed average may be applied, after any
required EEPROM save and verification has succeeded.

### Non-blocking operational tare

Operational tare now follows:

```text
t or deliberate D4 hold
    -> APP_STATE_TARE_SAMPLING
    -> collect 20 samples incrementally
    -> save and verify the candidate offset
    -> apply the candidate offset
    -> result pattern
    -> idle state
```

Serial `q` or a new D4 press cancels before another conversion is collected.
Cancellation, raw-read failure, the 5000 ms total timeout, save failure or
verification failure preserves the previous active offset.

### Non-blocking calibration

Calibration is represented by four explicit states:

```text
APP_STATE_CALIBRATION_WAITING_FOR_ZERO
APP_STATE_CALIBRATION_ZERO_SAMPLING
APP_STATE_CALIBRATION_WAITING_FOR_MASS
APP_STATE_CALIBRATION_MASS_SAMPLING
```

The zero phase stores and verifies its candidate tare before applying it and
advancing. The mass phase stores and verifies the calculated factor before the
new factor becomes the accepted persistent result.

Cancelling during an incomplete zero phase preserves the previous tare.
Cancelling after a completed zero phase keeps the newly stored tare and leaves
the previous calibration factor active.

### Explicit temporary-result state

Success and error indications now run inside:

```text
APP_STATE_RESULT_PATTERN
```

During a result pattern:

- UART input receives `Result indication is active.` and is discarded.
- D4 and D8 cannot interrupt the pattern or start new work.
- Presses born during the pattern remain suppressed until stable release.
- No rejected input is executed after returning to the saved state.

### Explicit busy-state input policy

While tare or calibration sampling is active:

- `q` cancels the current operation.
- D4 cancels the current operation.
- Other UART commands receive a current-state response and are discarded.
- D8 cannot start a second operation.
- Rejected input cannot remain queued for later execution.

### Removed blocking scale interfaces

The former compatibility APIs were removed:

```text
scale_tare()
scale_read_net_counts()
scale_read_weight()
```

Normal measurement now uses `scale_try_read_weight()`. Tare and calibration use
the incremental collector.

## Behaviour preserved from v1.1

- Startup never performs automatic tare.
- A missing or invalid tare enters `TARE_REQUIRED`.
- Stored calibration and tare records keep the same EEPROM layouts.
- Physical operational tare still requires a three-second D4 hold.
- Serial `t` remains an immediate service request from idle states.
- Physical calibration entry still requires a three-second D8 hold.
- Calibration zero persists tare independently from the factor.
- Transactional rollback preserves prior runtime values after failures.
- Negative calibration factors remain valid.
- Direct AVR production and Arduino-reference builds share application code.

No EEPROM migration is required when upgrading from `v1.1`.

## Physical validation

All ten planned hardware tests passed on the Arduino Nano, real HX711, load
cell, D4/D8 buttons and three LEDs:

- Valid stored tare and calibration recover after reset.
- A forced startup-not-ready condition enters the cooperative fault state.
- UART and physical tare cancellation preserve the previous offset.
- A cancellation press held beyond three seconds cannot start a later tare.
- Completed tare survives complete power loss.
- Calibration zero can be cancelled before or after its persistence boundary.
- Reference-mass collection can be cancelled without saving a partial factor.
- Missing reference mass produces a retryable error.
- Complete calibration persists both the new tare and factor.
- Inputs during result patterns are suppressed until release.
- UART and button handling remain responsive during 20-sample operations at
  10 SPS.

Detailed evidence is recorded in:

```text
docs/v1.2-non-blocking-application-validation.md
```

## Known limitations

This release intentionally retains:

- A generic latched startup fault rather than detailed fault categories.
- No watchdog or automatic runtime recovery policy.
- One EEPROM slot per persistent record and no wear levelling.
- No stable-weight detector, filtering or outlier rejection.
- Bounded synchronous EEPROM access and console transmission.
- Serial service commands without confirmation prompts.
- Compile-time thresholds and calibration mass.
- HX711 as the only measurement backend.
- ATmega328P Nano as the only production target.
- Physical HX711 power-down and power-up validation as a separate pending item.
