## Purpose

This milestone prevents an unexpected restart from redefining the current load as zero.

The firmware restores a validated tare offset from EEPROM. When no valid tare exists, normal level indication remains disabled until the operator deliberately establishes a new zero reference.

---

## Implemented behaviour

### Startup

```text
valid stored tare
    → restore offset
    → begin normal measurement

missing or invalid stored tare
    → enter TARE_REQUIRED
    → disable normal level indication
    → blink all three LEDs slowly
```

Automatic startup tare has been removed.

### Manual physical tare

```text
short D4 press
    → ignored

hold D4 for approximately 3 seconds
    → measure tare
    → save and verify EEPROM
```

### Serial tare

```text
t
    → perform and persist tare immediately
```

### Clear stored tare

```text
z
    → invalidate the stored tare record
    → stop normal level indication
    → enter TARE_REQUIRED immediately
```

### Calibration

Confirming the zero stage now:

```text
measure tare
    → save and verify tare
    → advance to reference-mass stage
```

If tare sampling or storage fails, calibration remains at the zero stage.

Cancelling calibration after a successful zero confirmation keeps the newly stored tare while preserving the previous calibration factor.

---

## Persistent storage layout

```text
EEPROM 0–11
    calibration record

EEPROM 12–23
    tare record

EEPROM 24 onward
    unused
```

The calibration and tare records are independent and non-overlapping.

## Physical validation

### 1. Missing tare at startup

Procedure:

1. Start with a valid tare.
2. Send `z`.
3. Confirm that normal measurement stops immediately.
4. Confirm that all three LEDs blink together slowly.
5. Reset or power-cycle the board.

Verified:

- The firmware reports that no valid tare is stored.
- Normal level indication remains disabled.
- All three LEDs continue blinking slowly.
- Existing load is not silently converted into zero.

Result:

```text
PASS
```

### 2. Serial tare from TARE_REQUIRED

Procedure:

1. Place the empty permanent container on the platform.
2. Send `t`.
3. Wait for tare completion and EEPROM verification.
4. Reset the board.

Verified:

- Tare completes successfully.
- The stored offset is reported.
- Normal measurement starts.
- The same offset is restored after reset.

Result:

```text
PASS
```

### 3. Physical tare requires a hold

Procedure:

1. Start with a valid stored tare.
2. Press D4 briefly.
3. Confirm that the offset does not change.
4. Hold D4 for approximately three seconds.
5. Keep holding slightly longer than three seconds.

Verified:

- The short press does nothing.
- The long press triggers one tare.
- The tare is not repeated while the same press remains held.
- The new offset is stored and restored after reset.

Result:

```text
PASS
```

### 4. Power loss with load present

Procedure:

1. Establish a valid tare with the empty permanent container.
2. Add a known load.
3. Record the displayed weight.
4. Remove power while the load remains present.
5. Restore power without moving the load.

Verified:

- The stored tare is restored.
- The existing load is still reported.
- The load is not redefined as zero.

Result:

```text
PASS
```

### 5. Calibration from TARE_REQUIRED

Procedure:

1. Send `z`.
2. Place the empty permanent container on the platform.
3. Start calibration.
4. Confirm the zero stage.
5. Cancel during the reference-mass stage.
6. Reset the board.

Verified:

- Zero confirmation measures and stores tare.
- Calibration advances only after storage verification.
- Cancelling keeps the previous calibration factor.
- The newly stored tare is restored after reset.

Result:

```text
PASS
```

### 6. Complete calibration

Procedure:

1. Start calibration.
2. Confirm zero with the empty permanent container.
3. Apply the reference mass.
4. Complete and save calibration.
5. Reset the board.

Verified:

- The tare record is valid.
- The calibration record is valid.
- Both records are restored independently.
- Measurements remain correct after reset.

Result:

```text
PASS
```

### 7. Calibration cancellation with held TARE button

Procedure:

1. Start calibration.
2. Press and continue holding D4 for longer than three seconds.

Verified:

- Calibration cancels immediately.
- The same physical press does not later trigger a tare.
- A new tare requires releasing D4 and starting a new hold.

Result:

```text
PASS
```

### 8. Console clear commands remain independent

Procedure:

1. Store valid calibration and tare records.
2. Send `x`.
3. Reset and verify that tare still loads.
4. Restore calibration if needed.
5. Send `z`.
6. Reset and verify that calibration behaviour remains independent.

Verified:

```text
x
    → clears calibration only

z
    → clears tare only
```

## Known limitations

This milestone intentionally retains:

- Blocking tare sample collection.
- Blocking calibration operations.
- One EEPROM slot per record.
- No EEPROM wear levelling.
- No stable-weight detector before tare or calibration.
- No watchdog integration.
- No brown-out reset diagnosis.
- Serial service commands without confirmation prompts.

These items are deferred to later milestones.
